# v0.3.8 — Statement ingest

Branch `feat/v0.3.8-bank-import`. Written after probing sixteen real and synthetic
statements from nine institutions; the evidence behind every decision here is in
`scratch-workspace/probe/` and the findings report.

---

## The governing rule

> **No preset may ever be the reason a statement is accepted. A preset can only make
> acceptance _fast_. Acceptance itself is always arithmetic.**

This is the whole point of the release, and it is falsifiable. Today the opposite holds:
`rb.ts:4` requires spaces in dates, Raiffeisenbank's January 2025 template prints
`3.1.2025`, and the file imports "successfully" with **zero rows** — then stores its
`contentHash`, so the corrected re-import is later refused as a duplicate. A regex is
currently the arbiter of truth. After this release it is a hypothesis, and the balances
are the arbiter.

Two honest qualifications, so nobody discovers them in month three:

- **For tabular formats (CSV/XLSX) generic discovery is strong.** A reader with no bank
  knowledge found mBank's and Revolut's amount and balance columns purely by arithmetic,
  including Revolut's `Amount − Fee` composite.
- **For PDF layouts it is materially weaker.** The same reader solved only 2 of 13 PDFs.
  Multi-line transaction records (Raiffeisenbank prints 3 physical lines per movement,
  Česká spořitelna 2–5) defeat naive segmentation. PDF stays **assisted extraction with a
  proof gate**, not universal parsing. Say this in the README too — "universal" was too
  strong a word for the PDF path.

## Scope

**In:** format-first routing · CAMT.053 · MT940 · OFX/QFX · ABO/GPC · lossless tabular
engine for CSV and XLSX · candidate generation and determinacy · proof classes P0–P4 with
lexical constraints · profile store, mapping wizard and drift handling · migration of the
five existing adapters onto the engine · OCR arbitration (tesseract.js, local, 5 languages)
· asynchronous queued processing with progress · per-row provenance · a GUI-blocking audit.

**Out:** bank APIs (PSD2 aggregators — v0.4.0; the only constraint honoured now is that an
API feed must land as the same canonical statement). Investment/holdings documents remain
routed to the investments module.

**No back-compatibility constraint.** Confirmed: only tests need adapting. `ParsedRow` may
be reshaped and `FINGERPRINT_VERSION` bumped freely.

## Phases

Each phase ends green: `npm run check && npm run lint && npm test`.

### Phase 0 — Bank the immediate wins (small, independent)

Ships value before any rewrite and creates the first regression test.

- Fix `rb.ts:4` and the period matcher at `rb.ts:51` to accept both `3.1.2025` and
  `1. 3. 2025`.
- Add `KS_Bank_01:2025.pdf` as a regression fixture — **assert non-zero rows and exact
  reconciliation**, not merely "parses".
- Make a zero-row parse from a statement that prints balances a **hard error**, never a
  success. This alone would have caught the bug.
- `ParsedStatement` gains `statedCreditTotalMinor`, `statedDebitTotalMinor`,
  `statedRowCount`. Every bank we hold prints at least the first two; mBank prints all
  three. Populate them in the existing five adapters.

### Phase 1 — Format-first router and the safety boundary

- `detect.ts` routes on **format sniffed from bytes**, then bank. The extension is not
  evidence.
- Fix the live lie in `+page.svelte:43`: `.xml,.ofx,.abo` are advertised and rejected.
- Safety boundary **before** any parser runs: signature check, compressed and decompressed
  size limits, sheet/row/column/cell caps, processing-time and memory ceilings, reject
  nested archives, never execute macros, never fetch external links, never recalculate
  formulas, treat cached formula values as untrusted. XLSX is a zip and uploads are
  untrusted; a decompression bomb is a real denial of service on a self-hosted box.
- `ingestFile` returns **many statements per file** — CAMT.053 carries several `<Stmt>`
  blocks and a workbook can hold a sheet per account. Each statement resolves its own
  account and reports its own counts.

### Phase 2 — Standards parsers

One parser each, no bank knowledge required.

| Format | Notes |
|---|---|
| CAMT.053 | ISO 20022. Mind the Czech Banking Association dialect (see `tkarabela/okane`, MIT). |
| MT940 | `:20: :25: :28C: :60F: :61: :86: :62F:` |
| OFX/QFX | SGML and XML variants |
| ABO/GPC | Fixed 128-char records; see below |

ABO is fully specified (ČS document 3-2267) and covers essentially every Czech bank. Three
traps, all confirmed from the spec:

1. **Amounts are already in haléře** — no decimal parsing at all.
2. **The sign is the posting code, not the amount**: `1` debit, `2` credit, `3` and `4` are
   _reversals_ — read as ordinary movements they land backwards.
3. **Account numbers may be permuted** into "vnitřní formát"
   (`C0C8C9C6C1C2C3C4C5C7P1…P6`), and the counter-account's bank code hides in the K-symbol
   field at positions 5–8 from the right — the only way to rebuild the `93531803/5500` form
   `pairing.ts` expects.

### Phase 3 — Lossless tabular engine (CSV + XLSX)

- **Extract as strings; never coerce during extraction.** Keep `displayText` alongside any
  typed value, plus `numberFormat`. For `counterpartyAccount`, `bankRef`, `variableSymbol`,
  `constantSymbol`, `specificSymbol`, IBAN and BIC the **displayed text is authoritative**.
  SheetJS turns `000123` into `123` and a 26-digit Polish NRB into a float; once leading
  zeros are gone nothing restores them.
- **Region detection before table parsing, for delimited text as well as spreadsheets.**
  mBank's most common row width is 2 — its metadata pairs. Its transactions are width 8,
  two-thirds down the file. "Dominant width" finds the wrong thing.
- Regions classified metadata / summary / transactions / footer. **Summary regions are kept
  as evidence** — that is where opening balances and stated totals live.
- **Transaction rows need a semantic exclusion rule.** mBank's closing balance is
  `;;;;;;#Saldo końcowe;106,59 PLN` — the same width as a transaction row, and a phantom
  movement to any width-based parser.
- Merged cells: expand the upper-left value across the **header area only**, never through
  data rows.
- Candidate generation across encoding × delimiter × quote × header row × footer cutoff.

### Phase 4 — The proof engine

**Ledger models are enumerated hypotheses, never assumptions:**

- signed amount column
- `credit − debit` **and** `debit − credit` two-column pairs
- amount net of a separate fee (`Amount − Fee`, Revolut)
- ascending **and** descending row order
- balance-after / balance-before / available / ledger balance

**Proof classes, ranked lexicographically** — proof class first, heuristic score only ever
breaks ties:

| | Evidence |
|---|---|
| **P4** | running chain + opening + closing + stated totals + row count |
| **P3** | complete running chain only |
| **P2** | aggregate closure; stronger when independent debit **and** credit totals agree |
| **P1** | endpoints only |
| **P0** | no arithmetic evidence |

**Lexical constraints gate every class.** Arithmetic closure alone is not proof: a uniform
1000× misreading of amounts _and_ balances closes the chain perfectly. Require consistent
decimal and grouping, monetary precision compatible with the currency, displayed text
agreeing with the inferred scale, identifier columns never reinterpreted as money, and
consistent negative markers (leading minus, trailing minus, parentheses).

**Sign is derived from the balance movement wherever a balance column exists**; a printed
`S`/`H`/`−`/`( )` is corroboration only. Evidence: OCR read `87,45 S` as `87,45 Ss` and a
strict match dropped the whole row while the amount itself was perfect. One glyph must
never decide a transaction's direction.

**Auto-import policy:**

```
P4 / P3 + lexical checks pass          -> import silently
P2 / P1 + every dimension determined   -> import silently
P2 / P1 + one dimension undetermined   -> ask about THAT DIMENSION ONLY
P0                                     -> ask, or use a verified saved profile
```

Determinacy tests, all proven against real files:

- **Date order** — any component > 12 settles it; else the stated period settles it (the US
  fixture has 14 dates all ≤ 12 and is resolved only by "March 1, 2025 through March 31,
  2025"); else ask. **Monotonicity is not evidence** — banks post in operational order.
- **Decimal separator** — a value carrying both separators settles it; a 3-digit group
  beside 2-digit groups settles it.
- **Amount vs balance** — if one column's consecutive differences equal another column's
  values, both are identified at once _and the file promotes to a chain proof_. Run this
  eagerly: several "no balance" exports do print one.

### Phase 5 — Profiles, wizard, drift

- Built-in profiles as JSON data files in the repo; user profiles in `import_profile`.
- Matched by **column signature plus filename pattern — never by position.** Firefly III's
  positional `roles` array breaks the moment a bank adds a column.
- Profile format is a strict superset of the prior art: encoding, header-name mapping,
  balance role, debit/credit pair, sign convention, decimal and grouping style, currency
  column, period source.
- **Drift re-opens the wizard pre-filled with the previous mapping** — "this export changed
  since last time" — never a bare error. Old files keep parsing under the old profile
  version.
- Export/import a profile as JSON so one mapped once can be contributed back.
- Multilingual header dictionary as a **data file, not constants** (`Datum` / `Fecha` /
  `Data` / `Dátum`, `Betrag` / `Importe` / `Kwota` / `Částka`, `Verwendungszweck` /
  `Concepto` / `Tytuł` / `Zpráva pro příjemce`). Column role comes from this dictionary
  **first**, value shape second — Fio's `Protiúčet` (`2600247495`) classifies as numeric and
  must never be offered to the arithmetic as an amount.

### Phase 6 — PDF and OCR arbitration

- Migrate the five adapters onto the engine; they become fast paths behind the proof gate.
- Amount assembly **spans cells**: CaixaBank's `-1 000,00 €` arrives as
  `-1 § 000,00 § €`. Beware the inverse trap — "space then three digits" also describes the
  gap between two columns (`300,00 377,93`); only join when the run before the space does
  not already carry a decimal.
- **OCR is arbitration, not fallback.** Text layers fail in ways that look like success:
  `pdftext.ts:18` rounds `y` to a 2-unit grid so staggered baselines merge or split rows,
  and two unrelated documents emit ligatures as separate items (`con § fi § rmation`,
  `fl § at rent`). Rendering the page gives an independent read of the same pixels.
- Statement-level arbitration: text layer first (free); if it fails the proof gate,
  rasterise and OCR; take whichever whole read reconciles; if neither, show both in review.
  **No cell-level splicing** — a spliced row exists in neither source read.
- Rasterise with `mupdf` (WASM, no native addons — verified on this Alpine base). OCR with
  `tesseract.js`, languages `eng ces pol deu spa`, **bundled not fetched** because "Nothing
  calls home" is a README promise.
- Row extraction uses **word bounding boxes and column geometry**, not text-line splitting.
  Line splitting with a rigid shape discards rows OCR read correctly.
- Detect **holdings snapshots** — balances but no movements — and route them to investments
  rather than failing to reconcile them.

### Phase 7 — Async pipeline and provenance

- Deterministic parsing stays inline and instant. Anything requiring rasterisation is
  **queued**; the upload returns immediately. Nothing blocks the GUI, ever.
- Queue shows depth and per-file progress; multiple files queue visibly.
- Single lease, one file at a time — tesseract is CPU-bound and parallel workers would
  starve the web server on a NAS. Reuse the lease-locking pattern in
  `calendar/sync/engine.ts`.
- **Provenance per row**: how it was read (parser / OCR / confirmed mapping), which proof
  passed, source file, and byte-line or sheet-range. Surfaced on the transaction and as a
  filter ("everything that came from OCR"). Store the winning candidate's evidence; rejected
  candidates are recomputed on demand since parsing is deterministic and originals are kept.

### Phase 8 — GUI-blocking audit

Sweep every server operation for work that blocks the interface — calendar sync, backups,
FX refresh, net-worth recomputation — and hold each to the same never-block rule. Report
findings even where no fix is needed.

## Schema

Migrations continue from `0043`.

- `statement` — `stated_credit_total_minor`, `stated_debit_total_minor`, `stated_row_count`,
  `proof_class`, `ledger_model`, `reconciliation_evidence` (jsonb).
- `import_profile` — id, name, bank, country, format, column signature, filename pattern,
  mapping (jsonb), version, verified flag, origin (built-in / user / imported).
- `transaction` — `source_method`, `proof_class`, `source_ref` (file, sheet/page, row).
- `bank` stops being a closed union. `BankId` in `types.ts:1` and `BANK_LABEL` in
  `ingest.ts:77` are replaced by a record with id, display name and country.
- `FINGERPRINT_VERSION` → 4.

## Tests

**Unit tables — cheaper and more targeted than fixtures.** Number and date conventions live
here, not in generated documents:

| Convention | Case |
|---|---|
| Zero-decimal currency | HUF `12 500 Ft` — the case `FINGERPRINT_VERSION` 3 exists for |
| Apostrophe grouping | CHF `1'234.55` |
| Lakh grouping | INR `12,34,567.89` — breaks every `\d{3}` assumption |
| Space grouping | `54 650.00`, `-1 000,00` |
| Parenthesised negative | `(48.71)` |
| Trailing minus | `1 234,56-` |
| Trailing-dot date | `2025.03.14.` |
| Timestamp date | `2026-06-30 09:32:29` |

**Golden fixtures** — every sample re-parses to identical `ParsedRow` sets and fingerprints.

**Regressions with a named cause:**

- `KS_Bank_01:2025.pdf` — RB January template, must yield non-zero rows and reconcile.
- **Cross-format fingerprint equality** — `72970193_260701_260731.csv` and `.pdf` are the
  same statement in two formats and must produce identical fingerprints. The file hashes
  differ, so only `fingerprint()` prevents a double import for anyone who downloads both.
- mBank footer row must not import as a phantom transaction.
- Fio `Protiúčet` must not be classified as an amount.
- Revolut `Amount − Fee` composite must be discovered.
- Robinhood holdings snapshot must route away, not fail to reconcile.
- OCR: rendered page reconciles to P4; degraded scan degrades to review, never to a wrong
  import.

## Open risks

- **PDF genericity is limited** — accepted and stated above; assisted, not universal.
- **Tesseract loses summary blocks** while reading transaction tables well, so stated totals
  may be unavailable on scans even where the format prints them. The chain is the dependable
  oracle there.
- **Image quality floor** — with naive line extraction only 300 dpi at high quality
  reconciled. Word-geometry extraction should lower this; measure again after Phase 6 and
  warn users below the measured floor.
