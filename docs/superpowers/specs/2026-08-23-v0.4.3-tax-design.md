# v0.4.3 — Tax statements hold many documents, and the Tax tab is rebuilt

**Status:** design, awaiting review
**Date:** 2026-08-23
**Branch:** `v0.4.3-tax`
**Follows:** `2026-08-19-v0.3.9-schema-lock-design.md`
**Design handoff:** `2026-08-23-tax-tab-handoff/README.md`

## Premise

Three things, in this order, because each depends on the one before it.

A tax statement can hold exactly one document. In practice a year's filing
arrives as several pieces of paper: the statement itself, the employer's annual
income confirmation, the broker's earnings report. There is nowhere to put the
second one.

Making a statement hold many documents means registering `tax_statement` in the
`entity` supertype, which is a schema change, which means rebuilding the running
instance from a backup — and the backup restore is broken. That defect is
unrelated to tax and predates this work, but it sits directly on the path.

With the statement's data model settled, the Tax screen is rebuilt to the design
handoff: grouped by year rather than by person·country, one chart rather than
six, one display currency for comparison with the filed figures kept native.

## Non-goals

- **Computing tax.** `src/lib/tax.ts` records what a statement said; it does not
  model brackets, allowances or residency. Unchanged.
- **Standalone earnings reports.** Every attachment hangs off a statement. A
  broker report that arrives before the statement waits, or the statement is
  created early with the figures filled in later.
- **A migration chain.** `drizzle/` keeps describing the schema as it is, in one
  baseline file. See Part 1.
- **Editing a document's shelf, expiry or filing from the tax screen.** The
  documents screen owns those.

# Part 0 — The backup restore is broken

**Sequenced before the reset in Part 1**, which cannot happen without it. Not a
separate release — it is part of this branch's work, it just has to exist before
a backup is taken. The defect means no backup taken to date can be restored.

**Observed.** Verified against a real Postgres on the current baseline:

```
DUMP HEADER: copy "person" ("id", …, "created_at", "entity_kind") from stdin;
DUMP FIELDS PER ROW: 11
DUMP COLS LISTED:    12
RESTORE RESULT: column "entity_kind" is a generated column
```

**Root cause.** `src/lib/server/backup/dump.ts:76` builds each table's column
list from `information_schema.columns` with no filter, so it names
`entity_kind` — the `GENERATED ALWAYS … STORED` column the entity supertype adds
to eleven tables. `COPY … TO STDOUT` correctly omits generated columns from the
data. Every dump therefore carries a header one column wider than its rows, and
Postgres rejects the header outright before the row count is even reached.

**Fix.** Filter the column query to `and is_generated = 'NEVER'`.

**Why it survived.** `tests/unit/backup.test.ts` covers `orderTables`, the
schedule policy and the directory guard. Nothing ever executed a dump and read
it back. New integration test `tests/integration/backup-round-trip.test.ts`:
seed rows across several entity-registered tables, call `dumpDatabase()`, apply
the emitted SQL into the same database after a truncate, and assert every row
returns with its values intact. A generated column reappearing in the header
fails it.

# Part 1 — `tax_statement` joins the entity supertype

## 1.1 Where the schema change goes

Folded into `drizzle/0000_baseline.sql`, not added as `0001`.

`tests/integration/baseline-migration.test.ts:38` asserts `migrationFiles()`
equals exactly `['0000_baseline.sql']`, and its comment states the policy: fold
the change into the baseline and migrate any live instance by hand. That test is
untouched and keeps meaning what it says. A fresh install — and every future
user — gets the amended baseline and needs nothing else.

Four edits:

1. `entity_kind_check` gains `'tax_statement'`.
2. The `FOREACH t IN ARRAY ARRAY[…]` registration loop gains `'tax_statement'`.
   It has a `created_at` column, so it takes the `has_created_at` branch and
   hands its own timestamp to the entity.
3. `ENTITY_KINDS` in `src/lib/enums.ts` gains `'tax_statement'`.
4. `person` gains a nullable `tax_view` jsonb column, for Part 3.4. Folded in
   here so the baseline is amended once and the instance is reset once.

`tests/integration/entity-supertype.test.ts` and `schema-invariants.test.ts`
iterate `ENTITY_KINDS` for the trigger pair, the CHECK constraint and the
no-orphans assertion, so the new kind is covered the moment it is listed.

## 1.2 Rebuilding the running instance

The dump is data-only; the schema comes from the app's own migrations on first
boot. So: take a backup on the Part 0 code, drop and re-create the database,
boot the new build so the amended baseline runs, restore the dump.

Then one statement, because a dump taken from the current schema holds no
`entity` rows for tax statements, and the restore sets
`session_replication_role = replica`, which suppresses the register trigger
during the load:

```sql
insert into entity (id, kind, created_at)
select id, 'tax_statement', created_at from tax_statement
on conflict (id) do nothing;
```

Harmless if the trigger did fire. The full step-by-step goes in
`scratch-workspace/` as a one-off runbook — it is this instance's transition,
not something a new user ever runs.

**No boot-time entity reconciliation.** A backfill on every boot would quietly
mask a genuinely unregistered row, which is exactly what
`entity-supertype.test.ts` exists to catch. The trigger is the guarantee.

## 1.3 Attachments live in `document_link`

No `tax_statement_document` table. The far end of a `document_link` is an
`entity`, and `tax_statement` now is one — that is the whole reason the
supertype exists.

`tax_statement.document_id` **stays in place**, per the additive-only lock, but
stops being read or written. Its schema comment records that `document_link`
supersedes it. Keeping it as a "primary attachment" alongside the links would be
two sources of truth for one fact.

Backfill during the reset copies each non-null `document_id` into
`document_link`.

## 1.4 Attachment kind

Not a column. A picked kind determines the derived document name and applies a
matching tag, both through machinery that already exists.

`src/lib/tax.ts`:

```ts
export const ATTACHMENT_KINDS = [
	{ key: 'statement', label: 'Statement', noun: 'tax statement', tag: 'tax statement' },
	{
		key: 'employer',
		label: 'Employer earnings report',
		noun: 'employer earnings report',
		tag: 'employer report'
	},
	{
		key: 'broker',
		label: 'Broker earnings report',
		noun: 'broker earnings report',
		tag: 'broker report'
	},
	{ key: 'other', label: 'Other', noun: 'tax document', tag: 'tax' }
] as const;
```

`statementDocumentName(year, country, kind = 'statement', filename?)` extends the
existing function. The two-argument call still returns `2025 CZ tax statement`,
so `tests/integration/tax-statement-document.test.ts` stands unchanged. When
`filename` is supplied it appends ` · <filename>`; the caller supplies it only
when the derived name would otherwise collide with one already linked to the
same statement.

The tag is what lets the documents screen filter every broker report across all
years without a schema change.

# Part 2 — Server and domain

## 2.1 `src/lib/server/tax/index.ts`

- `StatementInput.attachment` becomes `attachments: StatementAttachment[]`, each
  carrying `storedName`, `ext`, `addedOn`, `kind`.
- **The statement row is inserted before its documents now**, reversing the
  current order: the `document_link` foreign key needs the statement's entity to
  exist. The comment explaining why the document went first is rewritten to
  explain why it no longer does. Still one transaction, so a failed save leaves
  neither the statement nor its paperwork.
- `attachDocumentsToStatement(statementId, attachments, handle)` — for each
  attachment, `insertDocumentAggregate` with `shelf: 'tax'`,
  `personIds: [personId]`, `tagNames: [kind.tag]`, then a `document_link` row to
  the statement. `saveStatement` calls this rather than duplicating the body.
- `detachDocument(statementId, documentId)` — deletes the one link row. Returns
  `{ ok: false }` when no row matched, so a stale page reports "no longer
  attached" instead of silently succeeding.
- `loadStatements()` additionally joins `document_link` to `document`, returning
  `attachments: { id, name, ext, file }[]` ordered by `document.addedOn`. It
  stops reading `documentId`.

## 2.2 `src/routes/(app)/tax/+page.server.ts`

- `?/save` reads `form.getAll('file')` and `form.getAll('fileKind')` in
  parallel and passes the list down. The existing "file on the volume before the
  row is" discipline extends to the batch: **every** upload is removed if the
  save refuses or throws, not just the first.
- `?/attach` — statement id, files, kind. For the expansion's own adder.
- `?/detach` — statement id, document id.
- `?/deleteAttachment` — document id, via the existing `deleteDocument()` in
  `$lib/server/documents/mutations`, which already cascades the links and
  unlinks the stored file.
- The "already on the Tax shelf" picker stays and now adds a link.

## 2.3 `src/lib/tax.ts` — `taxByYear`

New, beside `taxSeries` (which keeps its signature and any other callers). Shape
and rules are given in the handoff under "Server-side changes"; the load-bearing
ones repeated here because they are easy to get wrong:

- Convert **at year end** — `` `${s.year}-12-31` `` as the day. Today's rate for
  a 2018 filing restates history every time the rate table updates.
- Keep the ratio in bigint via `effectiveRatePct`. Never divide floats.
- Sum in minor units before converting where the currency is shared; convert
  each statement separately where it is not.
- Return years ascending. The matrix reverses; the chart wants ascending.

# Part 3 — The Tax tab

`docs/superpowers/specs/2026-08-23-tax-tab-handoff/README.md` is the
specification for this part: layout, copy, tokens, chart geometry, hover
behaviour and the four implementation traps. It is high fidelity and its values
are final. What follows is only what it leaves open or what this release
changes about it.

## 3.1 The person axis

`Both · <person A> · <person B>`, a `Segmented.svelte` control **above the chart
card**, governing both the chart and the matrix. `Both` sums the household per
country per year; picking a person filters both.

The handoff placed it above the matrix. It sits above the chart instead because
the chart re-renders on the same selection, and a control has to precede
everything it governs.

The summary band stays above the control and stays household-wide always — it is
the "overall" answer, and a band that changed in response to a control below it
would read backwards. Its labels say "household" explicitly.

## 3.2 Attachments in the expanded row

The handoff's single `🗂️ documentName` line becomes the attachments block from
Part 2. Order inside the figures block: figures → converted equivalent →
attachments → note → diverges → lines.

Each attachment row: the name links to `/files/{storedName}` in a new tab when
the document has a file, plain text otherwise; `⇥` detaches with no confirm
(nothing is destroyed); `🗑` deletes the document and its file behind the
documents screen's two-tap arm-then-commit pattern, never a `confirm()` — a
native dialog blocks the page. Arming is keyed by document id and cleared
whenever `data.statements` changes.

The adder is the block's last row: `<input type="file" name="file" multiple>`,
one kind select for the batch, an Attach button. Three broker PDFs at once is one
action; a mixed batch is two.

The handoff's `⋯` menu holds Delete for the **statement**. Its label reads
"Delete statement" so it cannot be confused with deleting an attachment.

## 3.3 The dialog

`TaxStatementDialog.svelte` keeps its "the statement itself" section — recording
a statement and filing its paper stays one act — with the single file input
becoming `multiple` and gaining the kind select, defaulting to Statement. The
attach note pluralises. `Existing.documentId` and the dialog's `documentId`
state are removed; the picker posts its value straight to the action.

## 3.4 Preference persistence

Chart mode, display currency and person selection persist per person in a
`tax_view` jsonb column on `person`, written through `/tax/prefs/+server.ts` —
the same shape as `overview_layout` and `/overview/layout/+server.ts`. The
column is folded into the baseline alongside Part 1's changes.

## 3.5 The flagged-cell rule

The handoff shows flagged cells but does not define the trigger. Defined here as:
a filing whose gross, converted to the display currency, falls below 5% of the
median converted gross across all filings. That catches the PL 368 case without
hard-coding a currency or a threshold amount, and it stays correct as the record
grows.

The expansion explains: _"Unusually small for a full year — check whether this
was a part-year filing or a units error on entry."_

## 3.6 The four `--series-*-soft` tokens

Added to `src/lib/styles/app.css` beside the `--series-*` set, with light-theme
values of their own, as the handoff specifies.

Their colour-vision separation is **unverified**. Each soft step holds its
parent's hue angle so hue separation carries over, but lightness separation does
not — pastels sit closer in lightness by construction. Re-measure all four for
protan and deutan separation, alpha-flattened, in both themes, and adjust
lightness rather than hue if a pair falls under threshold. This is a task in the
plan, not a pre-ship afterthought.

## 3.7 Deletions

`src/lib/charts/TaxCharts.svelte` is deleted, not edited.

# Part 4 — Verify the data first

**Before any code.** The handoff flags PL 2025 gross `368 PLN` and PL 2024
`155.07 PLN` — annual incomes of roughly €85 and €36. Either a units error on
entry or a part-year filing the statement does not describe.

Check the underlying rows in the live database. A units error there is also
skewing the blended rate the new summary band puts at the top of the screen, so
this is the first task in the plan, not a cleanup at the end.

assert rows return.

**Part 1.** Covered automatically once `tax_statement` joins `ENTITY_KINDS`:
`entity-supertype.test.ts` (register trigger, retire trigger, no orphans) and
`schema-invariants.test.ts` (the CHECK matches the TS const).

**Part 2.** `tax-statement-document.test.ts` extends —

- three attachments of different kinds file three documents on the Tax shelf
  against the person, each linked to the statement, each carrying its kind tag;
- two files of one kind get distinct names;
- detach removes the link and leaves the document standing;
- deleting an attachment removes the document and its stored file;
- deleting the statement leaves its documents on the shelf.

`domain-atomicity.test.ts` gains: a save that fails partway leaves no uploads on
the volume and no documents filed — the existing single-file guarantee, now for
a batch.

Unit tests for `statementDocumentName` across all four kinds, the two-argument
back-compatible call, and the filename-suffix collision rule; and for
`taxByYear` — year-end conversion, mixed currencies in one year, a year with one
jurisdiction, ascending order, and the bigint rate path.

**Part 3.** Component tests for the matrix's empty cell (`·`, not `—` and not
`0`), the flagged-cell threshold, the person filter, and the currency toggle
leaving native figures untouched.
