# v0.3.11 Polish — Part 0: One Vocabulary for Shape and Spacing — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the geometry of the product a shared vocabulary — radius, spacing, control height — delete the duplicated form-control CSS, and make the convention enforced rather than remembered, **without changing how a single screen looks**.

**Architecture:** Four layers, added in order. Tokens in `app.css`; global control styles that replace fifteen copied blocks; a `Field` primitive for the markup shape that genuinely repeats; and an ESLint rule that holds the line afterwards. Every step is CSS or a mechanical swap, guarded by pixel-comparison screenshots captured before anything changes.

**Tech Stack:** SvelteKit 2.70 (runes), Svelte 5, TypeScript, ESLint 10 flat config, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-20-v0.3.11-polish-design.md` — Part 0.

### The token scale (copy exactly — do not re-derive)

```
--radius-xs: 4px     --space-1: 2px      --control-h: 36px
--radius-sm: 6px     --space-2: 4px
--radius-md: 8px     --space-3: 6px
--radius-lg: 10px    --space-4: 8px
--radius-xl: 12px    --space-5: 10px
--radius-2xl: 16px   --space-6: 12px
--radius-pill: 999px --space-7: 14px
                     --space-8: 16px
```

These are **measured**, not chosen. A tidier scale of `{4,6,8,12,16}` was tested against the code and would have visibly changed 112 gaps and 62 radii. Do not "improve" this scale.

> **Executed 2026-08-21. The plan as written produced a guard that did not
> work, and three corrections were needed before it did. All are in the shipped
> spec file; this note records why, because the reasoning is not obvious from
> the result.**
>
> 1. **Its own Playwright project, not another file in `polish`.** The polish
>    specs mutate the database — one adds a property, one leaves a failed job in
>    the import queue. As a sibling file the baseline photographed different
>    screens depending on whether it ran alone or in a full suite. It now lives
>    in a `visual` project with `dependencies: ['polish']`, so the order is
>    fixed either way.
>
> 2. **`maxDiffPixels: 120`, not `maxDiffPixelRatio: 0.01`.** The ratio sounds
>    strict and is not: on a full-page shot it permits roughly 29,000 differing
>    pixels. Tested against a deliberate `.card` radius change of 10px → 22px,
>    it reported success.
>
> 3. **`threshold: 0.02`.** Even at 120 pixels the same change still passed.
>    `threshold` is the PER-PIXEL colour sensitivity, and its default of 0.2 was
>    swallowing the difference: card and page backgrounds sit close together in
>    the dark theme, so a re-rounded corner moves pixels by very little. The
>    built CSS was checked directly to prove the change really was reaching the
>    browser before this knob was touched.
>
> Four things move on their own and are masked, each found by reading the diff
> image rather than by guessing: Settings' uptime, Settings' last-backup line
> (timestamp and file count), the Calendar ICS feed path (its token is a secret
> regenerated on every database reset), and "last synced" on both.
>
> **Verified:** three consecutive clean runs, each with a full rebuild and
> database reset; and the 10px → 22px card change caught on eight screens.

```
/* ---- Form controls ----
   This recipe was copied into roughly fifteen component stylesheets, and had
   already drifted: `padding: 8px 11px` everywhere except the sign-in page,
   which said `9px 11px`. Nobody noticed, and nothing would have. One
   definition, next to `.btn`, which has worked this way all along.

   Bare element selectors on purpose. Most of the copies being deleted styled
   `input, select` directly, so this replaces them without touching markup. */
input,
select,
textarea {
	border: 1px solid var(--bd2);
	background: var(--card);
	color: var(--fg1);
	border-radius: var(--radius-md);
	padding: var(--space-4) 11px;
	font-size: var(--text-md);
	font-family: inherit;
	/* A grid or flex item will not shrink below its content without this, and a
	   file input reports the width of its button plus the filename. */
	min-width: 0;
}

/* Anything a person types into or presses in a form row shares one height, so
   `align-items: end` has nothing left to disagree about. */
input,
select,
.btn {
	height: var(--control-h);
	box-sizing: border-box;
}

/* A textarea is the exception: its height is its content. */
textarea {
	height: auto;
	min-height: calc(var(--control-h) * 2);
}

/* Checkboxes and radios keep their intrinsic size — a 36px checkbox is a
   button, not a checkbox. */
input[type='checkbox'],
input[type='radio'] {
	height: auto;
	min-width: auto;
	padding: 0;
}

/* A file input's height comes from its button, which no padding on the input
   itself can settle. Style the button to live inside the shared height. */
input[type='file'] {
	padding: 0 var(--space-4);
	font-size: var(--text-sm);
	line-height: calc(var(--control-h) - 2px);
}
input[type='file']::file-selector-button {
	margin: 0 9px 0 0;
	padding: 3px 10px;
	border: 1px solid var(--bd2);
	border-radius: var(--radius-sm);
	background: var(--bg2);
	color: var(--fg1);
	font: inherit;
	font-size: var(--text-sm);
	cursor: pointer;
}

/* `.field` was already a convention — defined independently in five files.
   This promotes it rather than inventing it. */
.field {
	display: flex;
	flex-direction: column;
	gap: var(--space-3);
	font-size: var(--text-sm);
	color: var(--fg3);
	min-width: 0;
}
```

```
	import type { Snippet } from 'svelte';

	// The label/caption/control shape, which appeared about twenty-nine times
	// with `.field` defined independently in five stylesheets.
	//
	// The control is a child rather than a prop: every input, select and custom
	// control in the product keeps working unchanged, and nothing has to be
	// taught a new API to be wrapped. A component that took `type` and `value`
	// would have to grow a case for each of them.
	let {
		label,
		hint,
		children
	}: { label: string; hint?: string; children: Snippet } = $props();

<label class="field">
	<span class="field-label">{label}</span>
	{@render children()}
	{#if hint}<span class="field-hint">{hint}</span>{/if}
</label>

<style>
	.field-label {
		/* Inherits .field's size and colour from app.css; only the weight is
		   local, because a caption is not body text. */
```

Create `eslint-rules/no-raw-geometry.js`:

```
// SPDX-License-Identifier: PolyForm-Noncommercial-1.0.0
// Geometry comes from the scale in app.css, not from a number somebody picked.
//
// Written here rather than pulled in as a plugin, following the licence rule
// beside it: a dependency that checks two CSS properties is a dependency to
// audit, pin and update forever.
//
// It reads the <style> block as TEXT. ESLint does not parse CSS inside a Svelte
// component, and adding a CSS parser to police `gap` and `border-radius` would
// cost more than it saves.
//
// `padding` is deliberately NOT covered. It was measured: 51 distinct
// two-value pairs whose horizontal component is dominated by odd numbers —
// 11px in 27 places, 14px in 20 — so a scale would mean restyling the product.
// Padding drift is a duplication problem, solved by the global control styles
// and the Field primitive, not by a scale.

const PROPERTIES = ['border-radius', 'gap', 'row-gap', 'column-gap'];
const EXEMPT = /\/\*\s*geometry-exempt\s*:\s*(.*?)\s*\*\//;

export default {
	meta: {
		type: 'problem',
		schema: [],
		messages: {
			rawGeometry:
				'{{prop}}: {{value}} is a raw value. Use a --radius-* or --space-* token from app.css, ' +
				'or mark it /* geometry-exempt: why */.',
			exemptionNeedsReason: 'A geometry exemption must say why: /* geometry-exempt: the reason */.'
		}
	},
	create(context) {
		return {
			Program(node) {
				const text = context.sourceCode.getText();
				const open = text.indexOf('<style');
				if (open === -1) return;
				const start = text.indexOf('>', open);
				const end = text.indexOf('</style>', start);
				if (start === -1 || end === -1) return;

				const lines = text.slice(start + 1, end).split('\n');

				// Indexed, NOT `for...of` with `lines.indexOf(line)`: indexOf returns
				// the FIRST line equal to this one, so in a stylesheet — where `}` and
				// blank lines repeat constantly — the previous-line lookup below would
				// read some unrelated part of the file.
				for (let i = 0; i < lines.length; i++) {
					const line = lines[i];

					const exemption = line.match(EXEMPT);
					if (exemption) {
						if (!exemption[1]) context.report({ node, messageId: 'exemptionNeedsReason' });
						continue;
					}
					// An exemption comment covers the declaration on the line after it.
					if (EXEMPT.test(lines[i - 1] ?? '')) continue;

					for (const prop of PROPERTIES) {
						const match = line.match(new RegExp(`(?<![-\\w])${prop}\\s*:\\s*([^;]+);`));
						if (!match) continue;
						const value = match[1].trim();
						// A token, a keyword, zero, or a relative unit is fine. Only a
						// bare pixel number is a choice somebody made alone.
						if (!/\d+px/.test(value)) continue;
						context.report({ node, messageId: 'rawGeometry', data: { prop, value } });
					}
				}
			}
		};
	}
};
```
