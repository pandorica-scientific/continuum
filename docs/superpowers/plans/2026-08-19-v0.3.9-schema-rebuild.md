# v0.3.9 Schema Rebuild Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the database schema so future features are additive, then collapse the 46 migrations into a single baseline `0000`.

**Architecture:** Work incrementally with ordinary numbered migrations, exactly as normal development — each task adds `drizzle/00NN_*.sql` and stays independently testable against the embedded-Postgres harness. Only the final task squashes everything into one baseline. Do **not** attempt to hand-write the baseline first: it is unreviewable and untestable until it is finished.

**Tech Stack:** SvelteKit, Drizzle ORM (`postgres-js`), PostgreSQL, Vitest, `embedded-postgres` for integration tests.

**Spec:** `docs/superpowers/specs/2026-08-19-v0.3.9-schema-lock-design.md`

## Global Constraints

- **Money storage does not change.** Every money column stays `bigint` minor units. Do not rescale any value. The zero-decimal currency defect is already fixed in `src/lib/money.ts` — do not "fix" it again.
- **No user data to migrate.** There are no deployments. Migrations may be destructive. Do not write compatibility shims or backfill guards for hypothetical existing rows beyond what these tasks specify for the developer's own database.
- **Schema is built by migrations, never `drizzle-kit push`.** Triggers and CHECK constraints are invisible to Drizzle; `push` produces a database missing them.
- **Every enum-like column gets a CHECK generated from a TypeScript `const`.** No new bare `text` column with values documented only in a comment.
- **Every foreign key gets a covering index.** Enforced by test from Task 1 onward.
- **Naming, locked:** tables singular `snake_case`; PK `id`; FK `<table>_id`; money `*_minor` (`bigint`); instants `*_at` (`timestamptz`); dates `*_on` (`date`); indexes `<table>_<cols>_idx`. The bare column `day` on `currency_rate` and the snapshot tables is an allowlisted exception.
- **Commands:** `npm test` (vitest), `npm run check` (svelte-check), `npm run lint`, `npm run db:generate`.
- **Scratch files go in `scratch-workspace/`**, which is gitignored. The Postgres harness already writes there.

```ts
import { ALL_MIGRATIONS, startPostgres, type Harness } from './harness';

/**
 * Conventions the schema is locked to as of v0.3.9.
 *
 * These are not style checks. Each one encodes a defect class the schema has
 * already been bitten by, and each is cheap enough to run on every push.
 */
let harness: Harness;

beforeAll(async () => {
	harness = await startPostgres('schema-invariants', { max: 1 });
	await harness.applyMigrations(ALL_MIGRATIONS);
}, 120_000);

afterAll(async () => {
	await harness?.stop();
});

describe('foreign keys', () => {
	it('every foreign key has a covering index on its own columns', async () => {
		const rows = await harness.sql<{ table: string; columns: string }[]>`
			select
				c.relname as table,
				string_agg(a.attname, ',' order by k.ord) as columns
			from pg_constraint fk
			join pg_class c on c.oid = fk.conrelid
			cross join lateral unnest(fk.conkey) with ordinality as k(attnum, ord)
			join pg_attribute a on a.attrelid = fk.conrelid and a.attnum = k.attnum
			where fk.contype = 'f'
			  and c.relnamespace = 'public'::regnamespace
			group by fk.oid, c.relname
		`;

		const indexes = await harness.sql<{ table: string; columns: string }[]>`
			select
				c.relname as table,
				string_agg(a.attname, ',' order by k.ord) as columns
			from pg_index i
			join pg_class c on c.oid = i.indrelid
			cross join lateral unnest(i.indkey::int[]) with ordinality as k(attnum, ord)
			join pg_attribute a on a.attrelid = i.indrelid and a.attnum = k.attnum
			where c.relnamespace = 'public'::regnamespace
			group by i.indexrelid, c.relname
		`;

		// An index covers a foreign key when the key's columns are a PREFIX of the
		// index's columns — a lookup by (a) is served by an index on (a, b), but
		// not by one on (b, a).
		const covered = (fk: { table: string; columns: string }) =>
			indexes.some((ix) => ix.table === fk.table && `${ix.columns},`.startsWith(`${fk.columns},`));

		const uncovered = rows.filter((fk) => !covered(fk)).map((fk) => `${fk.table}(${fk.columns})`);
		expect(uncovered).toEqual([]);
	});
});
```

```ts
/**
 * Every enum-like column, and its permitted values.
 *
 * One array per column, used twice: to type the Drizzle column, and to generate
 * the CHECK constraint. They cannot drift, because there is only one of them.
 *
 * Postgres ENUM types are deliberately NOT used: a value cannot be dropped or
 * reordered without recreating the type and every column that uses it, which
 * fights an additive-only schema. A CHECK is one DROP/ADD pair.
 */
export const ENUMS = {
	'person.role': ['admin', 'member'],
	'account.bank': ['fio', 'revolut', 'mbank', 'rb', 'cs', 'kb', 'caixabank', 'other'],
	'account.kind': ['current', 'savings', 'brokerage'],
	'property.kind': ['lived', 'rented'],
	'property_bill.source': ['manual', 'meter'],
	'loan.kind': ['mortgage', 'car', 'consumer', 'family'],
	'loan.regime': ['fixed_period', 'fixed_term', 'floating'],
	'loan.day_count': ['30/360', 'act/365', 'act/360'],
	'loan.accrual_style': ['payment', 'calendar'],
	'loan_event.kind': ['payment', 'extra_payment', 'refix', 'fee', 'balance'],
	'transaction.review_state': ['auto', 'needs_review', 'confirmed'],
	'transfer_pair.state': ['auto', 'proposed', 'confirmed', 'rejected'],
	'import_job.state': ['queued', 'running', 'done', 'failed'],
	'import_profile.source': ['delimited', 'xlsx'],
	'import_profile.origin': ['builtin', 'user', 'imported'],
	'rule.provenance': ['learned', 'manual'],
	'document.expiry_verb': ['expires', 'ends', 'renews'],
	'calendar_account.provider': ['icloud', 'google'],
	'calendar_conflict.resolution': ['local-won', 'remote-won', 'wrote-back']
} as const satisfies Record<string, readonly string[]>;

export type EnumKey = keyof typeof ENUMS;
export type EnumValue<K extends EnumKey> = (typeof ENUMS)[K][number];

/** `<table>_<column>_check` — the locked constraint name. */
export function checkName(key: string): string {
	return `${key.replace('.', '_')}_check`;
}

/** The CHECK body for one column, e.g. `role in ('admin','member')`. */
export function checkBody(key: string): string {
	const column = key.split('.')[1];
	const values = ENUMS[key as EnumKey].map((v) => `'${v}'`).join(', ');
	return `${column} in (${values})`;
}
```

**Deliberately excluded**, because their values are open-ended rather than a closed set: `document.shelf` and `category.group_key` (user-extensible), `import_file.source_method` / `proof_class` / `ledger_model` (the import engine's own vocabulary, which changes with parser work), `calendar_event.category`, `contact.category`, `broker_operation.type` (the broker's vocabulary, not ours). Do not add these; a CHECK on a set that grows is a migration every time it grows.

```ts
import { ENUMS, checkName } from '$lib/server/db/schema-enums';

describe('enum columns', () => {
	it('every declared enum has a matching CHECK constraint in the database', async () => {
		const rows = await harness.sql<{ name: string; definition: string }[]>`
			select conname as name, pg_get_constraintdef(oid) as definition
			from pg_constraint
			where contype = 'c' and connamespace = 'public'::regnamespace
		`;
		const byName = new Map(rows.map((r) => [r.name, r.definition]));

		for (const key of Object.keys(ENUMS)) {
			const constraint = byName.get(checkName(key));
			expect(constraint, `missing CHECK for ${key}`).toBeDefined();

			// Every declared value must appear in the constraint body, and the
			// constraint must not permit a value the array does not list.
			const quoted = constraint!.match(/'[^']*'/g) ?? [];
			const inConstraint = new Set(quoted.map((q) => q.slice(1, -1)));
			const declared = new Set<string>(ENUMS[key as keyof typeof ENUMS]);
			expect(
				[...declared].filter((v) => !inConstraint.has(v)),
				`${key}: missing in DB`
			).toEqual([]);
			expect(
				[...inConstraint].filter((v) => !declared.has(v)),
				`${key}: extra in DB`
			).toEqual([]);
		}
	});
});
```

- [ ] **Step 4: Write the migration**

Create `drizzle/0048_currency.sql`:

```sql
CREATE TABLE currency (
  code     text PRIMARY KEY,
  exponent smallint NOT NULL,
  name     text NOT NULL
);

-- Seeded at boot from CLDR by refreshCurrencies(). The two rows below exist
-- only so this migration can attach the foreign keys below in the same
-- transaction; the refresh replaces and extends them on first start.
INSERT INTO currency (code, exponent, name) VALUES
  ('CZK', 2, 'Czech Koruna'), ('EUR', 2, 'Euro')
  ON CONFLICT (code) DO NOTHING;

-- Any code not yet known becomes a currency row rather than blocking the FK.
-- This is a one-time repair of developer data, not a permanent behaviour.
INSERT INTO currency (code, exponent, name)
SELECT DISTINCT code, 2, code FROM (
  SELECT currency AS code FROM account
  UNION SELECT currency FROM transaction
  UNION SELECT original_currency FROM transaction WHERE original_currency IS NOT NULL
  UNION SELECT currency FROM property
  UNION SELECT currency FROM loan
  UNION SELECT amount_currency FROM document WHERE amount_currency IS NOT NULL
  UNION SELECT currency FROM tax_statement
  UNION SELECT currency FROM holding
  UNION SELECT currency FROM broker_operation
  UNION SELECT currency FROM broker_position
  UNION SELECT currency FROM portfolio_snapshot
  UNION SELECT currency FROM networth_snapshot
  UNION SELECT currency FROM broker_import_state
  UNION SELECT code FROM currency_rate
) t WHERE code IS NOT NULL AND code <> ''
```

```ts
import { sql } from 'drizzle-orm';
import { minorDigits } from '$lib/money';
import type { Queryable } from './index';

/**
 * Materialise CLDR's currency list into the `currency` table.
 *
 * The table exists for referential integrity Postgres can enforce, NOT as a
 * source of truth about currencies — `money.ts` remains that, and it reads
 * CLDR. Seeding ISO 4217 by hand would create a second answer free to drift
 * from the first, and the two genuinely disagree (ISO gives HUF two decimal
 * places; CLDR gives zero, which is how it is actually written).
 *
 * Upsert-only, never DELETE: a code that vanishes from a future runtime must
 * not take rows referencing it down with it.
 */
export async function refreshCurrencies(handle: Queryable): Promise<number> {
	const codes =
		typeof Intl.supportedValuesOf === 'function' ? Intl.supportedValuesOf('currency') : [];
	if (codes.length === 0) return 0;

	const names = new Intl.DisplayNames(['en'], { type: 'currency' });
	const values = codes.map((code) => ({
		code,
		exponent: minorDigits(code),
		name: names.of(code) ?? code
	}));

	// One statement: a per-row round trip over ~300 currencies on every boot is
	// wasted time on a Raspberry Pi.
	await handle.execute(sql`
		insert into currency (code, exponent, name)
		select * from unnest(
			${sql.raw(`ARRAY[${values.map((v) => `'${v.code}'`).join(',')}]::text[]`)},
			${sql.raw(`ARRAY[${values.map((v) => v.exponent).join(',')}]::smallint[]`)},
			${sql.raw(`ARRAY[${values.map((v) => `'${v.name.replace(/'/g, "''")}'`).join(',')}]::text[]`)}
		)
		on conflict (code) do update
			set exponent = excluded.exponent, name = excluded.name
	`);
	return values.length;
}
```

```ts
/**
 * Register a new record in the supertype and return its id.
 *
 * Every linkable row is created through this, inside the same transaction as
 * the concrete insert. Skipping it is not a discipline question: the concrete
 * table's composite foreign key refuses the row.

export async function insertEntity(handle: Queryable, kind: EntityKind): Promise<string> {
	const rows = await handle.execute<{ id: string }>(
		sql`insert into entity (id, kind) values (gen_random_uuid(), ${kind}) returning id`
	);
	return rows[0].id;
}
```

- [ ] **Step 2: Write the equivalence test**

Create `tests/integration/baseline-migration.test.ts`:

```ts
import { afterAll, beforeAll, describe, expect, it } from 'vitest';
import { ALL_MIGRATIONS, migrationFiles, startPostgres, type Harness } from './harness';

let harness: Harness;

beforeAll(async () => {
	harness = await startPostgres('baseline-migration', { max: 1 });
	await harness.applyMigrations(ALL_MIGRATIONS);
}, 120_000);

afterAll(async () => {
	await harness?.stop();
});

describe('baseline migration', () => {
	it('is the only migration', () => {
		expect(migrationFiles()).toEqual(['0000_baseline.sql']);
	});

	it('creates every table, constraint and trigger the app needs', async () => {
		const tables = await harness.sql<{ tablename: string }[]>`
			select tablename from pg_tables where schemaname = 'public' order by tablename`;
		const names = tables.map((t) => t.tablename);
		expect(names).toContain('entity');
		expect(names).toContain('tag_link');
		expect(names).toContain('currency');
		expect(names).toContain('job');
		expect(names).not.toContain('import_job');
		expect(names).not.toContain('document_person');

		// The trigger and partial index that Drizzle cannot generate. If the
		// baseline was produced by db:generate alone, these are missing.
		const [{ n: triggers }] = await harness.sql<{ n: number }[]>`
			select count(*)::int as n from pg_trigger
			where tgname = 'transfer_pair_legs_trg' or tgname like '%_retire_entity_trg'`;
		expect(triggers).toBeGreaterThan(0);

		const [{ n: partial }] = await harness.sql<{ n: number }[]>`
			select count(*)::int as n from pg_indexes
			where indexname = 'property_bill_meter_property_idx'`;
		expect(partial).toBe(1);
	});
});
```
