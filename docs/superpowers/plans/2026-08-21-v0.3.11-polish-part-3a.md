### Task 1: Make the additive-only guard precise

`baseline-migration.test.ts:39` rejects any post-baseline migration containing `drop constraint`. Task 2 must widen a CHECK constraint, which in PostgreSQL is drop-then-add. The guard's stated rule is "never drop or retype something, because the baseline is the only rebuild this schema gets" — that is about **losing** things. Widening a CHECK loses nothing.

So the guard becomes precise rather than being bypassed: a constraint may be dropped **only if the same migration adds it back**.

**Files:** Modify `tests/integration/baseline-migration.test.ts`

- [ ] **Step 1: Replace the check with one that distinguishes widening from removal**

The regex stays for tables, columns and retypes. For constraints, a drop is permitted only when the same file re-adds a constraint of that name.

- [ ] **Step 2: Add tests for the guard itself**

Three synthetic SQL strings asserted directly, so the guard is tested rather than merely applied: a bare `DROP CONSTRAINT` is rejected; a drop followed by an `ADD CONSTRAINT` of the same name is allowed; a drop followed by an add of a _different_ name is rejected.

- [ ] **Step 3: Run, verify, stage.** `npx vitest run tests/integration/baseline-migration.test.ts`
