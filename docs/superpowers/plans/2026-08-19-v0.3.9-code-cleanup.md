# v0.3.9 Code Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Leave `src/` with no dead exports, no loose modules in `src/lib/server`, no comment that restates its code, and a licence header on every file that an ESLint rule keeps there.

**Architecture:** Four independent sweeps, ordered so each shrinks the surface of the next: delete first, then move, then read, then stamp. The module moves exploit the fact that `$lib/server/x` resolves to both `x.ts` and `x/index.ts`, so a domain becomes a directory without a single import changing; only the five cross-cutting modules that move into `system/` change any caller. Two invariants are left behind as enforcement — a unit test for the directory rule and an ESLint rule for the header — because a cleanup nobody can re-break is the only kind worth doing.

**Tech Stack:** TypeScript, SvelteKit, Vitest, ESLint flat config, Prettier.

**Spec:** `docs/superpowers/specs/2026-08-19-v0.3.9-schema-lock-design.md`, Part 3 (§3.1–§3.4). Acceptance criteria 9 and 10.

## Global Constraints

- **Licence identifier, exactly:** `PolyForm-Noncommercial-1.0.0`. `LICENSE.md` at the repository root already carries the full text; nothing about the licence itself is being decided here.
- **The header line, exactly:** `// SPDX-License-Identifier: PolyForm-Noncommercial-1.0.0`.
- **No behaviour changes.** Every task in this plan is a rename, a deletion, a comment or a header. Any diff that changes what the program does is a mistake in that task, not a bonus.
- **`npm test`, `npm run check` and `npm run lint` pass at the end of every task.** One pre-existing failure is expected and is not this plan's: `tests/acceptance/corpus.test.ts` refuses `RK_Bank_01:2025.pdf` at P0 where the corpus expects a 28-row P1 import. It fails on `main` too. Any _other_ failure is caused by the task in hand.
- **`npm run test:e2e` passes** at the end of Task 4 and Task 6, the two tasks that move files the running app imports.
- **No new dependencies.** The ESLint rule is written inline in `eslint.config.js` rather than pulling in a header plugin.
- **Nothing loose in `src/lib/server`** when the plan is done: that directory contains directories only.

### Task 1: Dead code sweep

Spec §3.1. The v0.3.8 session removed eight unreachable exports and a whole
portable-profile layer, so the yield here is known to be real.

**Files:**

- Create: `scripts/unused-exports.mjs`

- Modify: whichever files the scan convicts

**Interfaces:**

- [ ] **Step 1: Write the scan**

Create `scripts/unused-exports.mjs`:

```js
// Exported names that no OTHER file mentions. Advisory, not a gate: a name
// reached only through `import * as x` looks unused here and is not, which is
// why this prints a list for a person to judge rather than failing a build.
//
// Run it, then prove each candidate by deleting it and running `npm run check`.
// The compiler is the authority; this only says where to look.
import { readFileSync } from 'node:fs';
import { execSync } from 'node:child_process';

const sources = execSync("find src -name '*.ts' -not -name '*.d.ts'", { encoding: 'utf8' })
	.trim()
	.split('\n');
const everything = execSync("find src tests -name '*.ts' -o -name '*.svelte'", {
	encoding: 'utf8'
})
	.trim()
	.split('\n');
const corpus = new Map(everything.map((file) => [file, readFileSync(file, 'utf8')]));

const declaration =
	/^export\s+(?:async\s+)?(const|let|function|class|interface|type|enum)\s+([A-Za-z_$][\w$]*)/gm;

const hits = [];
for (const file of sources) {
	for (const [, kind, name] of (corpus.get(file) ?? '').matchAll(declaration)) {
		const mentioned = [...corpus].some(
			([other, text]) => other !== file && new RegExp(`\\b${name}\\b`).test(text)
		);
		if (!mentioned) hits.push(`${file}  ${kind} ${name}`);
	}
}

console.log(hits.join('\n'));
console.log(`\n${hits.length} exported names are mentioned in no other file.`);
```

Add to `package.json` scripts, after `fetch:tessdata`:

```json
"scan:unused": "node scripts/unused-exports.mjs"
```

- [ ] **Step 2: Run it and read the list**

Run: `npm run scan:unused`

Expected at the time of writing: 190 candidates — 144 types and 46 values.
The two groups need different judgement:

- A **type or interface** in the list is usually not dead, only over-exported:
  it is used inside its own file as a return or parameter annotation. Dropping
  the `export` keyword is the fix, not deleting the declaration.
- A **value** in the list is a real candidate for deletion.

- [ ] **Step 3: Discount the two known false-positive families before deleting anything**

Do not delete either of these on the scan's word:

1. **Drizzle tables.** `src/lib/server/db/schema/*.ts` exports are consumed
   through `import * as schema`, which the scan cannot see. `transferPairLeg`
   and `markTransferRule` appear in the list and are real tables that the
   database writes. Leave every schema export alone.
2. **Constants a test asserts by value rather than by name**, e.g. the
   `MAX_*` limits in `src/lib/server/import/safety.ts`.

- [ ] **Step 4: Delete the values that are genuinely unreachable, one commit's worth at a time**

Start with the ones the schema work already orphaned — the per-pair tag setters
left behind when thirteen link tables collapsed into three:

```

```

- [ ] **Step 5: Un-export the types nothing outside their file names**

For each type candidate, remove the `export` keyword and run `npm run check`.

- [ ] **Step 6: Leave the unreachable branches alone, and say why**

```ts
import { readdirSync, statSync } from 'node:fs';
import { join } from 'node:path';
import { describe, expect, it } from 'vitest';

/**
 * `src/lib/server` held twenty loose files beside nine directories, so where a
 * new domain belonged was a coin toss and the answer drifted: `calendar.ts` sat
 * beside `calendar/`, `policy.ts` beside `auth/policy.ts`, `demo.ts` beside
 * `home/demo.ts`.
 *
 * One rule fixes that permanently — a domain is a directory — and it is only a
 * rule if something checks it. `$lib/server/x` resolves to `x/index.ts` exactly
 * as it resolved to `x.ts`, so obeying it costs no caller anything.
 */
describe('src/lib/server', () => {
	it('holds directories only', () => {
		const loose = readdirSync('src/lib/server').filter((entry) =>
			statSync(join('src/lib/server', entry)).isFile()
		);
		expect(loose).toEqual([]);
	});

	it('gives every directory an entry point', () => {
		// A directory with no index.ts cannot be imported as a unit, which is the
		// whole point of the rule above.
		const missing = readdirSync('src/lib/server')
			.filter((entry) => statSync(join('src/lib/server', entry)).isDirectory())
			.filter((dir) => !readdirSync(join('src/lib/server', dir)).includes('index.ts'));
		expect(missing).toEqual([]);
	});
});
```

### Task 6: Licence headers, enforced

Spec §3.4 and acceptance criterion 9. 287 files in `src/` — 215 TypeScript and
72 Svelte — none of which carry a header today. `package.json` has no `license`
field at all, while `LICENSE.md` has carried PolyForm Noncommercial 1.0.0 all
along.

A rule that only holds because someone remembered it does not hold, so the
header is enforced by ESLint and the rule is fixable, which is also how the 287
files get stamped in the first place.

**Files:**

- Modify: `eslint.config.js`
- Modify: `package.json`
- Modify: all 287 files under `src/`, by `eslint --fix`

**Interfaces:**

- Produces: ESLint rule `licence/header`, `--fix`-able, error severity, covering `**/*.ts` and `**/*.svelte` under `src/`.

- [ ] **Step 1: Write the rule**

In `eslint.config.js`, above the exported config:

```js
const LICENCE_HEADER = '// SPDX-License-Identifier: PolyForm-Noncommercial-1.0.0';

// Written here rather than pulled in as a plugin: it is twenty lines, and a
// dependency that stamps a comment is a dependency to audit, pin and update
// forever.
//
// `.svelte` files take the header inside the first <script> block, not as an
// HTML comment at the top of the file — a markup comment is part of the
// component's output, and the licence of the source does not belong in the DOM
// the user's browser receives.
const licence = {
	rules: {
		header: {
			meta: {
				type: 'problem',
				fixable: 'code',
				schema: [],
				messages: { missing: 'File is missing the SPDX licence header.' }
			},
			create(context) {
				return {
					Program(node) {
						const text = context.sourceCode.getText();
						if (text.includes(LICENCE_HEADER)) return;

						const isSvelte = context.filename.endsWith('.svelte');
						context.report({
							node,
							messageId: 'missing',
							fix(fixer) {
								if (!isSvelte) {
									return fixer.insertTextBeforeRange([0, 0], `${LICENCE_HEADER}\n`);
								}
								// After the opening <script ...> tag, so the header lands in the
								// component's script rather than in its markup.
								const open = text.indexOf('>', text.indexOf('<script'));
								if (open === -1) return null;
								return fixer.insertTextAfterRange([open + 1, open + 1], `\n\t${LICENCE_HEADER}`);
							}
						});
					}
				};
			}
		}
	}
};
```
